# Developer journey

1. Run Doctor and verify profile, encoding, and available capabilities.
2. Index the workspace and treat unresolved calls as uncertainty.
3. Review the active source, fix findings in the editor, and use native Problems.
4. Review the intended Git scope and retain JSON/SARIF evidence.
5. Record decisions in Journal and promote only reviewed entries to Project Memory.
6. When a real adapter exists, prepare the build, inspect command/environment, and provide named approval before execution.

Outcome: a change with reproducible evidence. Compilation is verified only with compiler identity, zero exit code, and a SHA-256 artifact.
