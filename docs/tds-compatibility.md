# TDS-VSCode compatibility

The product complements TDS-VSCode and does not register language services, compilation,
debugging, RPO, server or terminal contributions.

## Verified matrix

| Product | TDS-VSCode | VS Code | Platform | Result |
|---|---:|---:|---|---|
| 0.3.0 candidate | 2.0.16 | 1.133.0 | Windows x64 | PASS: isolated install, TDS activation, four product commands, zero command-ID conflicts, multi-root review, CP1252 decoding and LF byte preservation |
| 0.3.0 candidate | not installed | 1.95.3 | Windows x64 | PASS: minimum standalone product host |

The tested TDS manifest declares VS Code `^1.97.2`, so TDS coexistence is not claimed on the
product's standalone minimum 1.95.x line. Retest the newest supported TDS release before each
Marketplace release.

The official TDS documentation says TDS owns editing/language services, compilation, debug,
RPO and server workflows, and recommends Windows-1252 for legacy sources. See the
[official TDS-VSCode repository](https://github.com/totvs/tds-vscode).

## Reproducible UAT

Run `npm run test:vscode:tds` on a Windows machine with the official `TOTVS.tds-vscode`
extension installed. The test copies the extension into an isolated extensions directory and
uses temporary user data. It does not copy `.totvsls`, server registrations, keys, tokens or the
normal VS Code profile.

The UAT activates TDS in a two-folder workspace, verifies product/TDS command namespaces do not
collide, opens a Windows-1252 source containing accents, runs the packaged product review from
the second workspace root and confirms the original CP1252/LF bytes remain unchanged. It also
guards against indexing `.vscode/.advpl` sources generated by TDS.

This is coexistence proof, not AppServer/RPO compilation proof. TDS may perform its own network
checks when activated; those requests are not product telemetry and are not counted as an
offline product guarantee.
